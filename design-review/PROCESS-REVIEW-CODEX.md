## 优化清单

- **P0｜财务页面回归（1–2 人日）。** 把合成账本与可控请求接入 CI，防止误读小计。验收六态：加载、失败、真零、零收入、缺汇率、切期间保留旧值。与主表对金额、币种和期间，回退修复时用例应失败。
- **P0｜独立分发门禁（1–2 人日，分发前）。** 隔离版本线、更新地址与签名，未配置就关闭更新。补改动日期与第三方许可。验收时干净安装候选包，核对更新渠道，从下载页取得对应源码及构建脚本。
- **P1｜先写验收，再交接（0.5 人日）。** 沿用 PR 模板，先定期间应用、取消、清除与 Esc 的行为，给争议决定注明确认人，减少重复裁定。验收由独立复核者按最终 SHA 和样本复验，每个问题可追到处理结果。
- **P1｜补一条桌面冒烟（1 人日）。** 保留 Rust 检查。桌面相关改动验证内置引擎连接、导出手册的打开与 Esc、弹窗 Tab 和回焦，补齐运行缺口。验收附候选 SHA 与逐项结果。
- **P1｜变更同批交付双语文档（0.5 人日）。** 入口变更同批更新 README 和手册，避免误导。验收为双语导出成功，受影响入口逐项点验。
- **P2｜上游同步演练（0.5 人日）。** 在临时分支记录起止 SHA、实际冲突与解决理由，建立可重复流程。验收通过 `make test`、手册同步构建和受冲突路径复测。

**不要做。** 别设全仓覆盖率百分比门槛，现有缺口集中在页面和运行边界。别在每个 PR 跑五平台完整打包，优先跑受影响路径，完整矩阵留给发布。
