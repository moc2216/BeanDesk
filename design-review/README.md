# BeanDesk 设计外部评审包

> 目的：请外部评审者（Codex）对**分类色板与整体视觉**给出独立意见。
> 约束：只评审、不改代码；输出写到 `design-review/codex-review.md`。

## 产品背景

- 产品：BeanDesk，本地优先的复式记账桌面应用（Tauri + React），对接本地 Beancount 账本与 Fava。
- 用户：中文为主的个人/一人公司用户，账户里同时有 CNY、USD、USDT、BTC、ETH、证券代码（CN_510300、HK_1810）、AU9999。
- 界面语言：中文优先，支持英文；浅色/深色两套主题。
- 主色：靛蓝 `#4F6EF7`（已确认保留，不在本次讨论范围）。
- 明确约束：
  1. 不考虑色盲适配（用户明确表示无此需求）；
  2. 图表分类色在浅色卡片（#FFFFFF）与深色卡片（#16181D）上都要 ≥3:1（WCAG 非文本）；
  3. 红/绿留给涨跌语义，分类色不使用；
  4. 本次不改布局、字号、组件结构，只讨论配色与整体观感。

## 当前分类色板（已上线）

```
#4f6ef7  #12a594  #b45309  #8e4ec6  #0284c7  #d6409f  #a67c52  #8b8d98
```

现状问题（内部判断）：
- 8 色冷暖失衡（冷色 5 个），饱和度与明度不齐；
- 棕色 `#a67c52` 在环图与树图里显脏；
- 整体像“图表库默认色板”，品牌感弱；功能上对比度已全部达标。

## 两个候选

### A · 克制色调
靛蓝单色阶 + 青绿 + 琥珀：
```
#4f6ef7  #243b9e  #0f766e  #b45309  #8fa6fb  #6b7280  #c7d2fe  #3a55d9
```
优点：统一、克制、显高级。风险：类别多时只能靠深浅；浅色阶上的白字不可读。

### B · 精修八色
```
#4f6ef7  #0f766e  #b45309  #7e22ce  #0284c7  #be185d  #9a5b3d  #64748b
```
优点：冷暖各半、明度接近、8 类仍可区分。风险：品牌感不如 A。

## 希望评审者回答

1. 当前色板的美感评分（1–10），最突出的 3 个问题，按影响排序。
2. A 与 B 选哪个更适合这个产品？给出理由，不要中庸。
3. 如果选 B，是否有具体 hex 调整建议？最多 3 处，说明理由。
4. 是否有比 A/B 更好的第三条路（例如少色相 + 明度阶）？只给一个，不要罗列。
5. 哪些现有做法应当保留，避免为了“好看”牺牲可读性？
