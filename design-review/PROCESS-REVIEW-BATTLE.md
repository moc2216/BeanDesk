# 复盘互评：OpenClaw vs GPT-6.2

两份独立复盘：`PROCESS-REVIEW-OPENCLAW.md`、`PROCESS-REVIEW-CODEX.md`。以下是逐项对照与裁决。

## 一、共识（双方都认为严重）

1. 财务状态后补验：失败态零储蓄率、未折算警告未及时覆盖；
2. 交互验收缺闭环：期间组件 18 次提交、清除行为反复；
3. CI 覆盖不足：只验 Web，桌面集成与手册导出没有门禁；
4. 文档漂移：功能改了 40+ 提交，说明书最后才补；
5. 上游同步没有演练，冲突热点未固化。

## 二、6.2 指出、我漏掉的

- **分发边界**：`tauri.conf.json` 仍是 0.2.9、`app.beandesk.desktop`、更新源指向 `SuperDaniel-cn/BeanDesk` 的 `latest.json`、公钥也是原作者的。独立发布前必须处理，否则用户安装后会去拉上游更新。
- **README/手册残留**：日历入口已移除，但双语 README 与手册仍指向它。
- **NOTICE 未提交/无日期**：合规材料不完整（本次已补，但仍需提交）。
- **REBUTTAL 与最终行为不一致**：文档建议“清除收进弹窗”，最终按用户要求恢复了 FilterX；文档需标注最终裁定。

## 三、我指出、6.2 未强调的

- 设计返工的根因是**验收标准后置**，不是审美能力；
- 验证脚手架缺失（seed 页、CDP、临时账本）导致每次验证成本高；
- 模型版本未固定导致评审重跑；
- 文档应纳入 Definition of Done，而不是收尾补。

## 四、分歧与裁决

| 议题 | 我的主张 | 6.2 主张 | 裁决 |
|---|---|---|---|
| 最高优先级 | CI 三件套 | 分发门禁 + 财务回归 | **采纳 6.2**：分发安全优先；CI 扩展排 P1 |
| 覆盖率 | 不设百分比 | 不设百分比 | 一致，不设 |
| 桌面 CI | 可选 | 必须有冒烟 | 折中：先加 Rust `cargo check`，桌面冒烟按改动触发 |
| 日历文档 | 未提 | 必须同步 | 采纳；在二次开发页注明本分支不含日历页 |
| 版本/更新源 | 未提 | 发布前必须处理 | 采纳，列为发布门禁，需用户拍板 |

## 五、合并后的结论

1. 发布前 P0：分发边界（identifier/版本/更新源/签名）+ 合规材料 + 文档残留；
2. 开发流程 P0：验收标准前置（含状态矩阵）+ 财务页面回归用例；
3. P1：CI 扩展（Rust check、docs build）、Playwright 冒烟、上游同步演练；
4. P2：token 单一来源、视觉回归、组件示例、i18n lint；
5. 不做：覆盖率百分比门槛、每 PR 全平台打包。
