# 开发流程复盘（OpenClaw 独立版）

范围：从设计体系落地到开源前收尾，约 41 个提交；不含原作者既有功能。
方法：读 git 历史、本次会话产物、design-review 文档、构建与验证记录。

## 一、结果面

已完成并有证据的部分：

- 会计期间：统一面板、先选后应用、期间常驻、FilterX 清除；
- 图表：稳定类别色、轴字对比度、空态/失败态/未折算警告、KPI 三态分离；
- 金额：固定符号、加密精度；
- 界面：表格统一、密度开关、字号台阶；
- 无障碍：焦点锁定、图表明细、减少动效、手册 Esc；
- 开源合规：NOTICE、二次开发说明页、原版权保留。

单元测试 191 项通过，tsc/lint 0 error，关键路径有截图与对比度计算。

## 二、真正的问题（按代价排序）

### 1. 没有先写“验收标准”，导致视觉返工

色板从现状到 A/B、再到 B 的三次修正、再到 6.2 的分歧裁决，至少 6 轮。
根因不是审美能力，而是先做图、后定义什么算对。如果一开始写清“8 类可区分、双主题 ≥3:1、深色不发灰、暖色不压大面积”，能少一半来回。

### 2. 验证发生在最后，而不是每步

失败态 KPI 显示 0.0%、空期间灰环、期间弹窗焦点逃逸，都是收尾阶段才发现。
根因：把“构建成功 + 截图好看”当成验证；没有为状态矩阵（加载/失败/真零/无定义/空筛选）设检查点。

### 3. 工具链摩擦被低估

- 全量 Tauri 构建约 1 分钟，dmg 打包曾卡住 9 分钟；
- headless 截图要反复起 dev server、造 seed 页；
- exec 输出截断、长命令超时，迫使拆步；
- Codex CLI 版本落后（0.144 vs 0.171），模型元数据缺失，重跑一次评审。

这些不是运气差，是缺少一套可复用的验证脚手架。

### 4. 跨 Agent 协作靠临时约定

前期让 Codex 评审时，没有结构化材料，靠一段长提示；后来才做 design-review 包（README、palette.json、截图、PROMPT）。
有效，但来得晚；且两次评审（6.1/6.2）结论不同，说明模型版本要固定并记录。

### 5. 文档与代码脱节到最后一刻

功能改了 40 多个提交，说明书没有同步；开源合规（NOTICE、二次开发章节）直到收尾才补。
根因：没有“改动即文档”的 Definition of Done。

### 6. 测试覆盖偏科

191 个单测集中在格式化、账本模型；UI 状态、焦点、密度、空态全靠手测截图。
没有组件测试，也没有视觉回归基线。

### 7. 上游分叉策略缺位

41 个提交后才讨论如何同步上游；冲突热点（Charts、time-filter、docs）没有提前标注。

## 三、优化清单（按优先级）

### P0（开源前就该有）

1. 每个任务先写 5 条验收标准（含状态矩阵），再动手；验收不过不算完成。
2. CI 三件套：lint、tsc、bun test，PR 必过；再加 docs build。
3. UI 冒烟脚本：Playwright 覆盖期间选择、清除、图表空态、失败态、焦点锁定；用 seed localStorage。
4. 改动即文档：功能 PR 必须同时更新二次开发说明页；模板里加勾选项。

### P1（开源后两周内）

5. 设计 token 单一来源：颜色/字号/间距集中在 tokens 文件，附对比度单测，避免 hex 散落。
6. 视觉回归：固定账本 + 固定视口，截图基线对比（浅/深、宽/窄）。
7. 可访问性测试：axe 扫描 + Tab 序列断言（焦点不逃逸）。
8. 上游同步节奏：每月 merge upstream，冲突热点写成清单。
9. 额度与模型记录：每次外部模型评审记录模型名、tokens、结论文件，避免重跑。

### P2（有余力）

10. 组件层 story/示例，减少“改一处、看全站”的回归成本；
11. i18n lint（禁止硬编码中文/英文文案）；
12. 发布自动化（版本号、CHANGELOG、签名）。

## 四、给这个仓库的具体动作

- 增加 .github/workflows/ci.yml（web lint/test/tsc + docs build）；
- 增加 CONTRIBUTING.md：分支、提交信息、文档同步要求；
- 增加 CHANGELOG.md：按模块记录本次二次开发；
- 把 design-review/ 转为 docs/design/ 或加入 .gitignore，避免评审材料混入发布物；
- 保留 SECONDARY-DEVELOPMENT.md 与 NOTICE（已完成）。

## 五、结论

这次交付的质量靠后期密集验证兜住了，但过程成本偏高。
最值得改的不是审美，而是把验收前移、把验证脚本化、把文档纳入完成定义。
